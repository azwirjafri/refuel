# Refuel V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the existing static fuel dashboard as an editorial monthly-budgeting workspace with clearer trends and new budget KPIs.

**Architecture:** Preserve the dependency-free HTML/CSS/ES-module application. Add pure budget calculations to `data.js`, evolve the canvas chart for the new metric and comparison views, and rebuild the semantic markup, styles, and rendering orchestration.

**Tech Stack:** HTML5, CSS3, JavaScript ES modules, Canvas 2D, Node built-in tests.

**Spec:** `docs/superpowers/specs/2026-11-06-refuel-v2-design.md`

## Global Constraints

- No third-party runtime dependencies or new backend.
- Do not merge into `main`; work stays in the existing isolated worktree.
- Preserve Google Sheets loading, demo fallback, filters, and CSV schema.
- Derive all figures from filtered data and clearly identify periods.
- No fuel-economy claims without distance data.
- Keyboard access, visible focus, mobile layouts, textual chart summaries, and reduced motion are required.

## Review Focus

- Empty or single-record selections: show unavailable comparisons and cadence rather than misleading zeroes; test in Task 1 and inspect in Task 4.
- Partial latest months: label month-to-date and disclose full-month comparison; test helper inputs in Task 1 and inspect in Task 4.
- Vehicle/fuel filters: previous-month comparisons retain those filters while looking before the selected range; test in Task 1.
- Long vehicle names and narrow screens: data remains readable without page overflow; inspect at mobile width in Task 4.
- Empty chart data: clear old chart/tooltips and expose a useful no-data message; test visually in Task 4.
